# pm-workflow-doc-refactor

PM 专用 skill——文档重构。对目标文档做结构、逻辑、表达三层面的优化，不改变事实内容。

## 触发规则

| 触发器 | 行为 |
|--------|------|
| `重构 <file>` / `优化文档` / `review 下` | 读目标文件 → 分析 → 输出优化方案 |
| `整理文档` / `优化结构` | 同上 |
| 用户选中一段文档后说 `review` | 分析选中文档 |

## 语言要求

| 输出类型 | 语言 |
|----------|------|
| 分析报告 | **简体中文** |
| 优化后的文档 | 保持原文语言 |

## 三层面检查清单

### 结构（Structure）

- [ ] 章节层级 ≤ 3（## → ### → 加粗/列表）
- [ ] 同级章节粒度均衡（无"一段 2 行 vs 一段 50 行"）
- [ ] 相关内容是否分散在多个章节？（是 → 合并）
- [ ] 是否有重复段落？（是 → 去重，保留一处）
- [ ] 信息架构：概览 → 细节 → 参考（而不是混排）

### 逻辑（Logic）

- [ ] 概念在前、解释在后（不先抛术语再补定义）
- [ ] 阅读顺序：规则在前、例外在后
- [ ] 依赖关系清晰（A 引用 B，B 必须在 A 之前或邻近）
- [ ] 表格 vs 列表选择正确：
  - 表格：多属性对比、行列有关联
  - 列表：平级条目、无对比需求
- [ ] 无循环引用、无自相矛盾

### 表达（Expression）

- [ ] 删冗余修饰词（"非常""实际上""请注意""需要指出的是"）
- [ ] 删可推导信息（"如前所述""综上所述"）
- [ ] 统一术语：全文同一概念用同一词
- [ ] 短句优先：>40 字长句考虑拆
- [ ] 中文为主，技术术语保留英文原文
- [ ] 否定句改为肯定句（"不允许不 release" → "必须 release"）

## 步骤

1. **读全貌**：通读目标文档（或粘贴内容），理解整体信息架构
2. **输出分析报告**：
   ```
   ## 结构问题
   - <问题 1>（位置：<section>）
   
   ## 逻辑问题
   - <问题 1>
   
   ## 表达问题
   - <问题 1>
   
   ## 建议
   按优先级列出重构动作（A→B→C），说明理由
   ```
3. **用户确认**：等用户说"重构"/"执行"后再动笔
4. **执行重构**：按确认的方案修改文件
5. **输出对比**：改动前后行数对比 + 结构变化摘要

## 关键边界

- **不改变事实内容**：不改数据/规则/约束，只改组织形式
- **不增删章节**：除非用户明确说"删掉这段"
- **不引入新术语**：用文档已有的词汇体系
- **保持引用有效**：修改章节名时同步更新交叉引用
- **OC1.4 先想清楚再动手**：不确定处向开发者确认

## 输出格式

```markdown
## <N> 处结构问题

| # | 问题 | 位置 | 建议 |
|---|------|------|------|

## <N> 处逻辑问题

| # | 问题 | 位置 | 建议 |
|---|------|------|------|

## <N> 处表达问题

| # | 问题 | 位置 | 建议 |
|---|------|------|------|

## 建议操作

1. <操作 1>（理由）
2. <操作 2>
...

请确认后执行。
```

## 参考：常见模式

| 模式 | 问题 | 修正 |
|------|------|------|
| 编号列表做长篇流程描述 | 扫描困难 | 改为表格（步骤/动作/约束） |
| 两处讲同一件事 | 冗余 | 保留信息更完整的一处，另一处改为引用 |
| Agent 专属规则散落 | 查找困难 | 内联到 Agent 行 |
| 正例/反例分两段 | 啰嗦 | 合并为"写/不写"两行 |
| "请注意""需要指出的是" | 废话 | 删 |
| 章节标题含动词 | 过长 | 缩为名词短语 |
